# Uncredentialed player-body Sandbox

The repository-root image runs only the admitted or staging player program as the unprivileged `abl-agent` identity. The reviewed image contains no signing service, model client, database client, core/storage credential, private-storage key, Agent Drive authority, or baked-in Blaxel control-plane credential. The third live run showed that Blaxel mounted its workload-identity token mode `0644`; the corrected initializer fails before `READY` unless that exact provider file and any `BL_ENV_VAR_PATH` file can be made root-only and an actual uid-10101 read attempt returns `EACCES`. Run `-05` live-proved that boundary through a real token rotation. The body manifest requests `extraArgs.iptables=enabled`, which Blaxel documents as required to enable kernel iptables support in a Sandbox.

Initialization first starts a sanitized, unprivileged diagnostic server on the reserved Sandbox API port. It exposes only `GET`/`HEAD /abl-init-status`; process, filesystem, terminal, and every other route return `404`, and invalid markers are never echoed. The server receives no inherited environment and remains available with `FAILED:<stage>:<code>` if configuration, proxy, iptables, or capability installation fails. It is stopped before the supported Sandbox API takes over the same port.

The root entrypoint parses the broker URL as a bare HTTPS origin and verifies that Blaxel supplied nonempty proxy configuration either directly or through `BL_ENV_VAR_PATH`. It extracts exactly one pinned provider identity-token path from the raw `{{file(...)}}` proxy template, rejects every other path or malformed template, makes the token and mounted environment file root-owned mode `0400`, and drops to uid/gid `10101` to prove both reads fail. URL parsing, proxy-file inspection, denial probes, and the local diagnostic readiness probe run under `env -i`; capability inputs must use canonical Base64. The exact pinned Sandbox API is version `0.2.50`, commit `bfecd2e7da6a726d6bbd8c010b511a6f9fc43121`; its credential-hiding loopback proxy uses stable port `49152`, recorded with the image and binary hashes in [`blaxel-sandbox-api.lock.json`](./blaxel-sandbox-api.lock.json). Root installs IPv4 owner rules that let UID 10101 reach only `127.0.0.1:49152`, rejects every other IPv4 route, and rejects all IPv6 routes for that uid. Once the Sandbox API starts, it resolves rotating platform credentials internally, binds that loopback proxy, and merges the platform CA. The immutable agent launcher uses the constant credential-free loopback URL and root-owned CA path and does not inherit the raw proxy template or workload token through its environment. The Blaxel allowlist contains only the fixed-broker private-preview host. This kernel-plus-proxy composition is necessary because [Blaxel domain filtering](https://docs.blaxel.ai/Sandboxes/Proxy-domains) relies on clients honoring proxy variables and is not routing-level enforcement; credential absence still requires the live filesystem and rotation probes.

The entrypoint validates one short-lived operation-scoped capability supplied through a Blaxel secret environment field. It writes that capability to an agent-readable, mode-0400 file under `/run/abl-body-capability`, replaces its encoded environment value with an empty sentinel so the Sandbox API cannot rehydrate it from `BL_ENV_VAR_PATH`, then reasserts the provider-mounted `/workspace` as a nonsymlink directory owned by uid/gid `10101` with mode `0700`. It verifies those exact metadata and never recursively changes workspace contents. It then emits a root-owned read-only `READY` marker, stops the diagnostic server, and starts the supported Sandbox API with all user operations forced to `abl-agent`. The immutable launcher starts the player program with an allowlisted environment containing only the public DID/address, fixed-broker origin, credential-free loopback proxy, root-owned CA path, and expiring capability. The fixed-broker private-preview token is stored in Blaxel's write-only, encrypted proxy routing configuration and injected as `X-Blaxel-Preview-Token` only after the outbound request leaves the workload; it never enters the player runtime or capability directory.

The fixed broker runs in its own Sandbox from `apps/body-broker`. That boundary owns the narrowly scoped signing, encryption, model, core, and storage credentials and enforces route, method, path, DID, event-class, nonce, deadline, size, response, and capability policies. A compromise of the player-body Sandbox therefore does not reveal those credentials and cannot open a direct route to their upstream services.

The pinned Node base index resolves to amd64 manifest `sha256:4ba75f5bbd5a524d65af8ee8ec74a2df1d552c5f315de6ae61c5d2f5ae5ee0af` and arm64 manifest `sha256:eef7390dd102531230def809635c348c7e7cbe48e2d3f33a91953da6837d4d4d`. The Blaxel reference sandbox image is pinned to registry index digest `sha256:3bbf1ce15194f5aff6557d5b48a5a7c32b17b84b9bd94000a952130e08000ccb`; its linux/amd64 manifest is `sha256:e62a65ee685bcb3b4396756b4a02b5cea495c3580ff135a578be8458e2db1e2d`, and the extracted `sandbox-api` binary SHA-256 is `0c6130d53b3e4448ba120a84e5bcd71a6ae47674ed7b8d215c8e2f0a2b217076`.

The root [`Dockerfile`](../../Dockerfile) and [`blaxel.toml`](../../blaxel.toml) form a Blaxel-native custom-image project. Blaxel can build it with `bl push`; a local Docker daemon is optional. [`package-staging-body.ts`](../../scripts/package-staging-body.ts) produces the only supported staging body archive with macOS copyfile/xattr export disabled, then validates every raw tar member before the archive is eligible for upload. Image push and resource creation remain approval-gated external mutations. Static manifest and capability behavior are local evidence, not substitutes for the required live direct-egress, credential-read, metadata, subprocess, restart, replay, and token-expiry tests.

The first Gate 2 run on `2026-08-21` used an earlier same-Sandbox broker design and did not request Blaxel's kernel-networking extra argument. It failed closed when nftables returned exit code `3`; the player program never ran. That design is retained only in the [failure record](../../docs/evidence/GATE-02-FAILED-CLOSED.md). Do not restore the embedded broker, bypass the failed policy, or treat domain filtering alone as an isolation boundary. The current six-Sandbox amendment combines a separate fixed broker, explicit kernel iptables support, UID-level direct-egress rejection, and the broker-only platform proxy allowlist.

The second Gate 2 run used the six-Sandbox split but stopped before agent upload because every protected initialization stage still occurred before the Sandbox API, making the stage marker unreachable on failure. The [second failure record](../../docs/evidence/GATE-02-RUN-02-FAILED-CLOSED.md) preserves that result.

The third run live-proved the read-only diagnostic failure path, `READY`, Sandbox API handoff, iptables enforcement, loopback proxy/CA presence, and the tested direct socket denials. It then stopped before player upload because uid `10101` could read the Blaxel workload-identity token and the allowed fixed-broker private-preview request returned `401`. Run `-05` live-proved both corrections, the complete denial matrix, and Drive cross-path bypass denial. It then failed closed before extraction because the live `/workspace` mount was root-owned mode `0700` while the Sandbox API forced uid `10101`; the first archive was also safely rejected for a macOS AppleDouble entry. The [fourth mutating failure record](../../docs/evidence/GATE-02-RUN-05-FAILED-CLOSED.md) is authoritative. The current workspace and packaging corrections remain local until exact-runtime review and bounded live proof.
