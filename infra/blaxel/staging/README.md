This directory describes a temporary, single-workspace, pre-Genesis platform proof. The topology contains six private Sandboxes: player body, fixed broker, core API, private-storage broker, public API, and arena. Five token-protected private previews connect the fixed services; the player body has no preview. All Sandboxes have four-hour idle deletion policies and 24-hour terminated retention. The proof is rehearsal-only and cannot create recognized history.

The separate fixed-broker Sandbox is the fail-closed replacement for the embedded broker used during the first Gate 2 run. The body requests Blaxel kernel iptables support at creation time. A sanitized unprivileged diagnostic server first exposes only the nonsecret initialization stage and no mutation routes. Root then requires the pinned provider identity-token and mounted-environment files to be root-only and proves uid `10101` cannot read either one, pins that uid to the exact Sandbox API v0.2.50 credential-proxy tuple at `127.0.0.1:49152`, rejects every other IPv4 route and all IPv6 egress for that uid, installs the short-lived capability, stops diagnostics, and hands port 8080 to the supported Sandbox API. The agent launcher uses only the credential-free loopback proxy and root-owned CA; the platform proxy allowlist contains only the fixed-broker preview host. Blaxel proxy routing injects the preview header server-side, so the player runtime never holds that token. This composition is required because Blaxel documents domain filtering as proxy-environment based rather than routing-level enforcement.

The player body receives no signing key, database URL, model credential, core/storage credential, Drive credential, private-preview token, or control-plane authority. It receives one operation-scoped capability expiring within four hours. The fixed-broker preview token is a write-only encrypted value in the body's Blaxel proxy rule, not a runtime environment variable or file. The fixed broker holds narrowly scoped signing, encryption, model, core, and storage credentials and can reach only the configured core, private-storage, and model hosts. The body cannot reach those hosts directly. Provider permission hardening, token rotation, header injection, and kernel/proxy behavior remain mandatory live denial tests because these controls are platform-dependent.

The topology uses one path-permissioned Agent Drive; no Blaxel Volume is proposed. The Drive must be created atomically with both rules in [`drive-access.json`](./drive-access.json), read back exactly, and rejected before mount or write if either rule is missing or widened. The storage broker receives read-write authority only under `/ciphertext`; the public API receives read-write authority only under `/projections`; the player body and fixed broker receive no Drive label, mount, preview credential, S3 credential, or direct Drive authority. Agent Drive's S3 endpoint remains forbidden because the private-preview permission rules are not enforced there.

The body program is uploaded to the body Sandbox's ephemeral `/workspace` only after the Sandbox exists. It is reproducible from reviewed source and is not durable league history. Build the Founding Alpha image contexts outside the repository with `pnpm founding-alpha:prepare-images <external-directory>` (`pnpm staging:prepare-images` remains an equivalent compatibility alias). The root [`Dockerfile`](../../../Dockerfile) builds the separate uncredentialed body image. Every manifest requires an immutable image digest; mutable tags are prohibited.

Runtime secrets are supplied only through Blaxel secret environment fields and are replaced with empty sentinels after decoding so the pinned Sandbox API cannot reload them from the mounted environment file. The body-to-broker preview token instead uses Blaxel's encrypted, write-only proxy-routing secret. Never place preview tokens, capabilities, signing keys, service credentials, database URLs, model credentials, or storage bootstrap values in Git. The body launcher exposes only the fixed-broker origin, its short-lived capability, the public DID/address, the credential-free loopback proxy URL, and the root-owned CA path.
