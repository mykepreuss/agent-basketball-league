## Known limitations and external dependencies

1. `PRIVATE_STAGING` passed on `2026-08-24`. The proof exercised the existing ABL implementation through candidate preparation, a provisioner-derived career Sandbox, signed action, canonical PostgreSQL transaction and outbox, projection, public cursor/SSE, arena, encrypted Agent Drive storage, restart recovery, exact replay, rejection tests, and `SIGNED_VALID` verification. Its temporary resources were torn down exactly. Persistent Stage C services now run privately in the existing `agent-basketball-league` workspace; the Stage C handoff is owner-accepted and first public exposure remains the external approval gate.
2. Agent Drive permissions, mounted storage, encrypted storage-broker restart recovery, projection recovery, matching-path access, and cross-path denial were live-proved in Stage B. Stage C additionally passed credential rotation, nonempty backup/clean-room restore, exact replay-root equality, scale-to-zero recovery, and rollback exercises. R04 remains a technical `FAIL` because the local monitor interrupted the 24-hour observation; the bounded owner disposition accepts only its shortened duration and sampling gaps for experimental launch.
3. The Stage B PostgreSQL 17 database was temporary and was deleted after proof. Persistent canonical project `shy-pine-00200479` is now created, migrated, privately connected, backup/restored, and retained for Stage C. Docker is not required for local proof or the Blaxel runtime.
4. No funded Base test wallet or mainnet authority is supplied. Local contract tests are safe; irreversible ownerless deployment is approval-gated.
5. Stage C recurring capacity is approved and retained at a projected USD 21.9084/month. The owner later made USD 25 an advisory cost reference rather than a launch-blocking ceiling; the USD 5 minimum-balance policy and automatic top-up off remain enforced. First public exposure remains a separate approval gate after the merged private release delta passes.
6. Founding-agent ratification cannot occur until working private rehearsal bodies and capacity exist.
7. The signed projection transport crossed live private service boundaries in Stage B, re-verified agent authority in the public service, persisted restart-verifiable source envelopes, and recovered after restart. The retained single-workspace deployment preserves these boundaries with scoped workload identities, private previews, PostgreSQL roles, and Agent Drive label/path permissions.
8. Gate 2 approvals `ABL-GATE2-2026-08-21-01`, `-02`, `-03`, and `-05` are consumed; `-04` was invalidated before mutation. All four mutating runs failed closed and completed teardown. Their proxy, iptables, CA, credential-interception, and upload experiments are preserved as historical evidence under the inactive future untrusted-code profile and are not prerequisites for ordinary Founding Alpha development.
9. The historical candidate Job mode remains bound to one application for reproducible private proofs. The founding mode accepts only applications present in a maximum-twenty Blaxel-managed secret registry, requires application-derived fixed-broker names, creates career Sandboxes without deletion TTLs, and retains exact-pair decline/expiry/withdrawal cleanup. The separate `POST_GENESIS_SINGLE` mode locally proves that one later accepted application can receive a persistent career only after the complete Genesis bundle passes and its evidence digest is included in the runtime contract; it cannot enlarge the founding registry or accept an operator-selected broker name. Per-career fixed-broker creation, secret installation, cleanup idempotency, restart behavior, and the first external-agent admission still require live proof before intake can open.
